## 0. 本节课主线

这节课讲的不是“交换机长什么样”，而是 IP 报文离开主机前，二层到底做了什么。

```text
IP 报文要发出去
  -> 先判断目标是同网段还是异网段
  -> 找到当前这一跳要交给谁的 MAC
  -> 封装成以太网帧
  -> 交换机根据 MAC 地址表转发
```

核心句：

```text
二层看 MAC；交换机先学源 MAC，再用目的 MAC 查表转发。
```

能把这句话解释清楚，本节课主干就通了。

## 1. 从 IP 到二层

上一节课讲 IP 地址和掩码，比如 `/24` 表示前 24 位是网络位。今天继续往下问：IP 报文能不能直接丢到网线或光纤上？

不能。IP 是三层，下面还要经过二层封装。课堂里的关系可以这样放：

```text
应用层      HTTP、DNS、业务数据
传输层      TCP、UDP
网络层      IP、ICMP、路由
数据链路层  以太网、MAC、交换机、VLAN
物理层      网线、光纤、无线、电信号、光信号
```

二层的作用：**在当前这一跳链路上，把帧交给正确的设备。**

这里的“当前这一跳”可以是：

- 电脑到交换机。
- 交换机到交换机。
- 电脑到默认网关。

对比记忆：

| 问题 | 主要依赖 |
| --- | --- |
| 目标是不是同网段 | IP + 掩码 |
| 异网段下一跳是谁 | 路由表/默认网关 |
| 当前这一跳交给哪块网卡 | MAC 地址 |
| 交换机从哪个端口发出 | MAC 地址表 |

注意：以太网不是 IP。以太网是二层技术，IP 是三层技术。只是常见场景下，以太网帧里装的是 IP 报文，所以容易混。

## 2. 为什么有 IP 还要 MAC

IP 地址解决“目标在哪个网络、跨网络怎么走”的问题；MAC 地址解决“当前链路上交给哪块网卡”的问题。

例子：

```text
PC1: 192.168.1.1/24
PC2: 192.168.1.2/24
```

PC1 知道 PC2 的 IP 是 `192.168.1.2`，但以太网帧头必须写目的 MAC。如果不知道 PC2 的 MAC，帧就封不完整。

所以 PC1 会先发 ARP：

```text
谁的 IP 是 192.168.1.2？把你的 MAC 告诉我。
```

简单记：

```text
IP 负责逻辑寻址，MAC 负责当前这一跳的二层投递。
```

## 3. 以太网、共享介质和冲突

以太网不是某根网线，也不是交换机本身，而是一套二层通信规则。它规定：

- 以太网帧长什么样。
- 目的 MAC、源 MAC、类型字段放在哪里。
- 网卡收到帧后怎么判断是不是给自己的。
- 多台设备共享介质时怎么处理冲突。

早期以太网可以想成多台设备挂在同一根线上：

```text
A、B、C、D 共享同一段介质
A 一发，其他人都能听到
B 如果同时发，就和 A 冲突
```

这个会互相影响的范围叫**冲突域**。

传统以太网用 `CSMA/CD` 处理冲突：

- `CS`：发送前先听信道有没有人在用。
- `MA`：多台设备共享同一介质。
- `CD`：发送时检测是否发生冲突。

如果冲突，就随机等待后重发；多次冲突后，等待时间按指数方式拉长，也就是指数退避。

现在普通有线交换网络基本是全双工，传统冲突问题不明显了。但理解这段历史，有助于理解集线器为什么低效，也能帮助理解 Wi-Fi 这种共享空口为什么会竞争。

## 4. 集线器和交换机的差别

集线器 `Hub` 是物理层设备。它不认识 MAC，也没有表项。一个端口收到信号，就复制到其他端口。

集线器的问题：

- 所有端口共享带宽。
- 所有设备在同一个冲突域。
- 不知道目标是谁，只会复制。
- 看起来是星型连接，逻辑上仍像一根共享线。

同轴电缆时代：

```text
PC1 --- PC2 --- PC3 --- PC4
```

集线器时代：

```text
        PC1
         |
PC2 --- Hub --- PC3
         |
        PC4
```

接线方式变方便了，但通信逻辑仍然是共享。

交换机 `Switch` 的关键变化是：能看懂以太网帧里的 MAC 地址。

交换机收到帧后做两件事：

1. 看源 MAC，记住这个 MAC 从哪个端口来。
2. 看目的 MAC，查表决定从哪个端口出去。

对比：

| 项目 | 集线器 | 交换机 |
| --- | --- | --- |
| 工作层次 | 物理层 | 二层 |
| 是否看 MAC | 不看 | 看 |
| 转发方式 | 复制到其他端口 | 查 MAC 表 |
| 冲突域 | 所有端口一个大冲突域 | 每个端口隔开 |
| 广播域 | 一个 | 默认仍是一个 |

交换机解决了冲突域问题，但默认没有隔离广播域。广播域要靠后面的 VLAN 继续处理。

## 5. 以太网帧结构

二层传输的数据单位叫帧 `frame`。常见以太网帧结构：

```text
目的 MAC | 源 MAC | 类型/长度 | 数据 | FCS
6 字节   | 6 字节 | 2 字节    | 46-1500 字节 | 4 字节
```

有些资料也会画出前导码/SFD：

```text
前导码/SFD | 目的 MAC | 源 MAC | 类型/长度 | 数据 | FCS
```

需要重点理解的字段：

**目的 MAC**  
帧要交给谁。网卡先看它，判断是不是发给自己的。

**源 MAC**  
帧是谁发出来的。交换机学习 MAC 表时看的就是源 MAC。

**类型/长度**  
告诉接收方后面的数据是什么：

```text
0x0800 -> IPv4
0x0806 -> ARP
0x86DD -> IPv6
0x8100 -> VLAN 相关
```

**数据**  
常见情况下是 IP 报文，但不一定只能是 IP，也可能是 ARP 等其他内容。准确说，它是上层数据。

**FCS**  
校验字段。接收方重新计算后如果对不上，说明帧可能损坏，直接丢弃。

## 6. 封装和解封装

封装不是“真的套了很多层盒子”，而是在一串连续字节前面不断加头，最后加校验。

发送 HTTP 数据时大致是：

```text
HTTP 数据
[TCP 头] + HTTP 数据
[IP 头] + [TCP 头] + HTTP 数据
[以太网头] + [IP 头] + [TCP 头] + HTTP 数据 + [FCS]
```

类型字段的作用在这里很关键：

- 以太网头的类型字段告诉主机：后面是 IPv4、ARP 还是 IPv6。
- IP 头里的 `Protocol` 字段告诉主机：IP 里面是 TCP、UDP、ICMP 还是别的。
- TCP/UDP 再通过端口把数据交给对应应用。

计算机看到的是一串 `0` 和 `1`，必须靠这些字段决定下一步交给哪个协议处理。

普通二层交换机主要看二层信息：

```text
目的 MAC、源 MAC、VLAN、入端口、出端口
```

它通常不会继续解析 HTTP 内容。

## 7. MAC 地址和 MAC 地址表

MAC 地址通常是 48 位，常用十六进制表示：

```text
54-89-98-33-E3-31
00e0-fc99-9999
```

前 24 位一般是 OUI，可用于识别厂商。MAC 通常是网卡出厂写入，但现代系统里也可以改，所以不要理解成绝对不可变。

常见 MAC 类型：

- 单播 MAC：某一块网卡自己的地址。
- 广播 MAC：`FF-FF-FF-FF-FF-FF`，同广播域设备都要处理。
- 组播 MAC：如 `01-00-5E-xx-xx-xx`，发给一组接收者。

网卡收到帧后通常先看目的 MAC：

- 是自己的，收。
- 是广播，收。
- 是自己订阅的组播，收。
- 都不是，正常丢弃。

抓包时如果开了混杂模式，网卡可能把不是发给自己的帧也上送给 Wireshark，所以能看到更多内容。

交换机的 MAC 地址表大致记录：

```text
MAC 地址 -> 端口 -> VLAN -> 老化时间
```

基础阶段重点看前两个：

```text
AA-AA-AA-AA-AA-AA -> GE0/0/1
BB-BB-BB-BB-BB-BB -> GE0/0/2
```

这表示以后有人发给 `BB-BB-BB-BB-BB-BB`，交换机应从 `GE0/0/2` 发出。

动态 MAC 表项会老化：

- 设备持续通信，老化时间刷新。
- 长时间不发帧，表项删除。
- 设备换端口后，只要从新端口发帧，交换机会更新记录。

## 8. 交换机三个动作：学习、转发、泛洪

### 8.1 学习：学源 MAC

交换机每收到一个帧，先看源 MAC 和入端口。

```text
源 MAC: AA-AA-AA-AA-AA-AA
入端口: GE0/0/1
```

交换机记住：

```text
AA-AA-AA-AA-AA-AA 在 GE0/0/1 后面
```

它学的是源 MAC，不是目的 MAC。源 MAC 才能说明“这个设备从哪里来”。目的 MAC 只是“这次要送给谁”。

### 8.2 转发：目的已知就单口转

如果目的 MAC 在表里能查到，交换机只从对应端口发。

```text
MAC 表：
AA -> GE0/0/1
BB -> GE0/0/2

收到帧：
源 MAC: AA
目的 MAC: BB
入端口: GE0/0/1
```

交换机查到 `BB -> GE0/0/2`，就只从 `GE0/0/2` 转发。

如果查到目的端口和入端口相同，不再原路发回去。比如某端口下面接着 Hub，A 和 B 都在这个端口后面，A 发给 B 的帧已经能在下游共享介质里被 B 收到，交换机再发回去只会产生重复。

### 8.3 泛洪：不知道就先扩散

目的 MAC 不在表里时，交换机不知道往哪送，就会泛洪：

```text
从除了接收端口以外的所有同 VLAN 端口发出去。
```

常见触发场景：

- 未知单播：目的 MAC 是具体地址，但表里没有。
- 广播：目的 MAC 是 `FF-FF-FF-FF-FF-FF`。
- 部分组播：基础阶段先理解为发给一组设备。

未知单播和广播的区别：

```text
未知单播：知道要找谁，但不知道他在哪。
广播：本来就要喊给所有人听。
```

## 9. 第一次 ping 的完整过程

拓扑：

```text
PC1 --- GE0/0/1 [SW1] GE0/0/2 --- PC2
```

假设：

```text
PC1: 10.1.1.1/24，MAC-PC1
PC2: 10.1.1.2/24，MAC-PC2
交换机 MAC 表初始为空
```

### 9.1 PC1 判断目标同网段

PC1 根据 IP 和掩码判断：

```text
10.1.1.1/24 和 10.1.1.2/24 在同一个网段
```

所以它直接找 PC2 的 MAC，不需要先找网关。

### 9.2 PC1 发 ARP 广播

```text
目的 MAC: FF-FF-FF-FF-FF-FF
源 MAC: MAC-PC1
ARP 内容: 谁的 IP 是 10.1.1.2？请告诉 10.1.1.1
```

交换机从 `GE0/0/1` 收到后，先学习：

```text
MAC-PC1 -> GE0/0/1
```

然后发现目的 MAC 是广播地址，于是泛洪到其他同 VLAN 端口，比如 `GE0/0/2`。

### 9.3 PC2 回 ARP 应答

PC2 发现问的是自己，于是回复：

```text
目的 MAC: MAC-PC1
源 MAC: MAC-PC2
ARP 内容: 10.1.1.2 的 MAC 是 MAC-PC2
```

交换机从 `GE0/0/2` 收到后继续学习：

```text
MAC-PC2 -> GE0/0/2
```

再查目的 MAC：

```text
MAC-PC1 -> GE0/0/1
```

所以只从 `GE0/0/1` 发给 PC1。

### 9.4 后续 ICMP 单播转发

PC1 现在有了 ARP 缓存：

```text
10.1.1.2 -> MAC-PC2
```

后续 ping 的 ICMP 报文封装成：

```text
目的 MAC: MAC-PC2
源 MAC: MAC-PC1
数据: IP 报文，里面是 ICMP Echo Request
```

交换机查表发现 PC2 在 `GE0/0/2`，就精准转发。

压缩记忆：

```text
PC1 ARP 广播问 PC2 的 MAC。
交换机学到 PC1 在 GE0/0/1。
PC2 单播回复。
交换机学到 PC2 在 GE0/0/2。
后续 ICMP 按 MAC 表单播转发。
```

## 10. 同网段和异网段：ARP 问谁

ARP 不一定问最终目标，关键看目标是否同网段。

同网段：

```text
本机: 10.1.1.1/24
目标: 10.1.1.2
ARP 问: 谁的 IP 是 10.1.1.2？
```

异网段：

```text
本机: 192.168.1.10/24
网关: 192.168.1.1
目标: 8.8.8.8
ARP 问: 谁的 IP 是 192.168.1.1？
```

原因：`8.8.8.8` 不在当前二层网络里，本机广播问不到它。异网段流量要先交给默认网关。

关键句：

```text
IP 目的地址可以是远端，但二层目的 MAC 永远是当前这一跳的下一站。
```

Windows 查看路由和默认网关：

```powershell
route print
```

## 11. eNSP 实验复现

拓扑：

```text
PC1 --- GE0/0/1 [SW1] GE0/0/2 --- PC2
```

地址：

| 设备 | IP | 掩码 | 连接 |
| --- | --- | --- | --- |
| PC1 | `10.1.1.1` | `255.255.255.0` | SW1 `GE0/0/1` |
| PC2 | `10.1.1.2` | `255.255.255.0` | SW1 `GE0/0/2` |

两个 PC 同网段，不需要配置网关。交换机端口默认 VLAN 1，先不做 VLAN 配置。

### 11.1 查看初始 MAC 表

```text
system-view
display mac-address
```

一开始通常看不到这两台 PC 的动态 MAC 表项。

华为命令习惯：

- `display` 类似 Cisco 的 `show`。
- `Tab` 可以补全。
- `?` 查看后续参数。
- `<cr>` 表示可以直接回车。

### 11.2 PC1 ping PC2

PC1 执行：

```text
ping 10.1.1.2
```

第一次可能略慢，因为先发生 ARP。ping 通后，再看：

```text
display mac-address
```

应能看到类似：

```text
MAC-PC1    VLAN 1    GE0/0/1
MAC-PC2    VLAN 1    GE0/0/2
```

课堂现象：刚开始表里没有，ping 后多出两个 MAC，分别对应两台 PC 的端口。

### 11.3 抓包观察

重点看：

- `ARP Request`：目的 MAC 全 F，广播。
- `ARP Reply`：目的 MAC 是 PC1 的 MAC，单播。
- `ICMP Echo Request/Reply`：ARP 完成后，ping 正常往返。

过滤器：

```text
arp
icmp
eth.addr == 某个MAC地址
```

观察顺序：

```text
先看 ARP 广播为什么出现
再看交换机怎么学到两个 MAC
最后看 ICMP 为什么不再泛洪
```

## 12. 现网排障关联

课堂开头提到：同一个 OLT 下两个 ONU 之间传大文件慢，但访问外网正常；日常维护也经常要求看交换机 MAC 表。

这类问题可以先从二层角度想：

- 某个设备的 MAC 是从哪个端口学到的？
- 某端口下面是不是学到了过多 MAC？
- 同一个 MAC 是否在不同端口之间漂移？
- 目标 MAC 是否根本没有被交换机学到？

常见现象：

| 现象 | 可能方向 |
| --- | --- |
| 一个端口下 MAC 很多 | 下挂交换机、Hub、私接设备，或异常流量 |
| 同一 MAC 来回换端口 | 可能有环路、链路切换、无线漫游或配置问题 |
| 目标 MAC 一直学不到 | 对端没发帧、链路不通、VLAN 不一致 |
| 未知单播很多 | MAC 表缺失、单向流量、老化过快或异常流量 |

排障意识：

```text
同一二层范围内的慢或不通，不要只看 IP 路由；
也要看 MAC 学习、广播、泛洪、VLAN、环路。
```

## 13. 易混点

### 13.1 以太网不是 IP

以太网是二层，IP 是三层。以太网常装 IP，但不等于 IP。

### 13.2 交换机学的是源 MAC

目的 MAC 用来查表转发；源 MAC 才能说明设备从哪个端口来。

### 13.3 未知单播不是广播

未知单播：有明确目标，但交换机不知道目标在哪。  
广播：本来就是发给所有人。

### 13.4 ARP 问谁取决于同不同网段

同网段问目标主机。  
异网段问默认网关。

### 13.5 交换机默认不隔离广播域

交换机隔离冲突域，但同一 VLAN 内广播仍会扩散。

## 14. 复习主线

按这条线复述：

```text
IP 报文要发出去，先判断目标是不是同网段。
同网段 ARP 找目标 MAC，异网段 ARP 找网关 MAC。
拿到 MAC 后，把 IP 报文封装进以太网帧。
交换机收到帧，先学习源 MAC 和入端口。
再用目的 MAC 查 MAC 地址表。
查得到就单口转发，查不到就同 VLAN 泛洪。
对方一回复，交换机又能学到对方 MAC。
后续通信就变成精准单播。
```

## 15. 自测题

### 1. 二层技术解决什么问题？

解决当前链路或同一二层网络内，帧怎么交给正确设备的问题。它靠 MAC 地址、以太网帧和交换机转发机制工作。

### 2. 为什么有 IP 还需要 MAC？

IP 负责逻辑寻址和跨网络定位；以太网帧在当前链路上传输时必须写目的 MAC。

### 3. 交换机为什么学习源 MAC？

源 MAC 和入端口能说明“这个设备从哪里来”。交换机记录来时路，后面别人找这个 MAC 时就知道从哪个端口出去。

### 4. 什么时候会泛洪？

目的 MAC 未知、目的 MAC 是广播地址，或某些组播需要扩散时，会从除入端口以外的同 VLAN 端口发出去。

### 5. 第一次 ping 为什么可能慢一点？

因为第一次 ping 前通常要先 ARP。PC 要先问到目标或网关的 MAC，才能封装正式的 ICMP 报文。

### 6. ping 异网段地址时，ARP 问最终目标吗？

不问。异网段时问默认网关或下一跳的 MAC。最终目标 IP 不变，但二层目的 MAC 是网关的 MAC。

### 7. 集线器和交换机最本质的区别是什么？

集线器不看 MAC，只复制信号；交换机能学习 MAC 表，并按目的 MAC 查表转发。

### 8. 以太网帧的数据字段一定是 IP 吗？

不一定。常见是 IP，也可以是 ARP 等其他内容，具体看类型字段。

## 17. 下一节为什么讲 VLAN

交换机让每个端口隔开了冲突域，转发也比 Hub 聪明，但同一个 VLAN 里的广播仍会扩散。

设备少时问题不明显；设备多了以后，ARP 广播、未知单播、环路风险、业务隔离都会变成问题。

VLAN 要解决的是：

```text
在同一套物理交换网络上划分多个逻辑二层网络，
让广播只在自己的 VLAN 内传播。
```

所以，先把交换机和 MAC 表搞明白，下一节 VLAN 才能听得进去。
