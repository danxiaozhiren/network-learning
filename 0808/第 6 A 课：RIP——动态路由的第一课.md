## 1. 开场：让路由器学会“道听途说”（5 分钟）

**回顾第六课**：
我们用静态路由让三台路由器实现了全网互通。但每一跳都要手工配置——当有几十上百台路由器时，逐条添加路由不仅工作量巨大，而且路由器对“链路断了”这件事毫无感知，只能靠 NQA 之类的联动手段补救。

**引入新问题**：
- 如果一个汇聚环上有 10 台路由器，每台下挂十几个网段，你会在所有设备上逐个写静态路由吗？
- 能不能让路由器自己“互相通告、自动学习、自动收敛”？——这就是**动态路由协议**要解决的问题。
- 在学 OSPF 之前，我们先学一个更简单的动态路由协议——**RIP**。它虽然已经过时，但它是动态路由的“最小完整实现”，把所有核心概念都跑了一遍：协议怎么说话、怎么算路、怎么防环。

**课程目标**：今天我们把 RIP 彻底摸透，这样下一课学 OSPF 时，你只需要专注“它和 RIP 哪里不一样”，而不用从零理解“动态路由是什么”。

## 2. 补充知识：动态路由协议的两大家族（10 分钟）

### 2.1 静态 vs 动态（回顾与对比）

| 特性 | 静态路由 | 动态路由（RIP/OSPF 等） |
|------|----------|------------------------|
| 配置方式 | 手工逐条配置 | 自动学习与计算 |
| 拓扑变化响应 | 无感知（除非联动 NQA） | 自动收敛 |
| 资源消耗 | 无 CPU、带宽开销 | 需 CPU 计算、占用少量带宽传协议报文 |
| 适用场景 | 小规模、出口、临时链路 | 大规模内部网络 |

### 2.2 距离矢量 vs 链路状态——两大流派

动态路由协议分两类，**这是理解整个路由体系的分水岭**：

- **距离矢量（Distance Vector）**：代表是 RIP。每台路由器只把“我能到达哪些网络、距离多少”告诉邻居，邻居再转告别人——**道听途说**。它只关心方向和距离，不掌握全网拓扑。
- **链路状态（Link State）**：代表是 OSPF、ISIS。每台路由器把“我连接了谁、代价多少”广播出去，全网共同拼出一张完整拓扑图，各自独立计算最短路径——**共享地图**。

**现网类比**：RIP 是“一路问人怎么走”，OSPF 是“人手一张地图自己规划”。

### 2.3 RIP 的定位

RIP 在现网已被 OSPF/ISIS 取代（第 7 节详述）。学它的价值在于：它是动态路由的最小骨架，所有概念——选路、度量、通告、收敛、防环——在 OSPF 中全部复用。

## 3. RIP 的核心机制（25 分钟）

### 3.1 距离矢量思想——“把我知道的告诉邻居”

- 每台 RIP 路由器周期性（默认 **30 秒**）把自己的完整路由表发给邻居。
- 邻居收到后逐条比较：如果“你告诉我的路比我现在的更近（跳数更小）”，就更新路由表，下一跳指向你。
- 信息就是这样**一跳一跳传播**的：R1 从 R2 学到 10.0.2.0/24，再通告给 R3 时把跳数 +1。
- 这是 Bellman-Ford 算法的基本思想，简单但可靠。

### 3.2 度量值：跳数（Hop Count）

- RIP 的度量只有“跳数”：**每经过一台路由器 = 1 跳**，直连网段为 0 跳。
- 最大可用跳数 **15**，**16 = 不可达（无穷大）**。
- 缺点：只认跳数、不看带宽。一条“2 跳的百兆链路”会输给“3 跳的千兆链路”，选路粗糙。这是 RIP 被淘汰的原因之一。

### 3.3 三个关键定时器

| 定时器 | 默认值 | 作用 |
|--------|--------|------|
| 更新定时器 | 30s | 周期性向邻居发送完整路由表 |
| 老化定时器 | 180s | 6 个更新周期内没再收到某条路由的更新，将其标记为不可用 |
| 垃圾收集 | 120s | 老化后再等 120s（合计 300s），彻底删除该路由 |

> 现网不建议修改 RIP 定时器。记熟“30 秒说话、180 秒判断死亡”，对理解收敛时间很有帮助。

### 3.4 收敛与环路——“记数到无穷”

- **收敛**：链路发生变化到全网路由一致的时间。收敛期间，各路由器掌握的信息不一致，就可能出现环路。
- RIP 的经典毛病：两台路由器互相把下一跳指向对方，数据包在两者间反复弹跳，路由表里的跳数一路加到 16 才判定不可达——**“记数到无穷”**。这就是 RIP 慢收敛、易环路的根源。

### 3.5 防环四招

1. **水平分割（Split Horizon）**：从哪个接口学到的路由，不再从该接口通告回去。
2. **毒性逆转（Poison Reverse）**：更激进——主动向来源接口通告“这条路由的度量是 16”，明确告诉对方“这条路已断”。
3. **触发更新（Triggered Update）**：路由一变化立即通告，不等 30 秒周期，加速收敛。
4. **抑制计时器（Hold-down Timer）**：某路由被标记不可达后，在一定时间内不再接受来自其他路径的劣化信息，防止“坏消息转一圈又传回来”。

> 提示：OSPF 因为是链路状态 + SPF 算法，**天生无环**，根本不需要这几招——这是第 7 课的核心对比点。

## 4. RIPv1 与 RIPv2（10 分钟）

| 特性 | RIPv1 | RIPv2 |
|------|-------|-------|
| 无类（VLSM/CIDR） | 不支持，只能按主类（A/B/C 类）识别 | 支持 |
| 通告方式 | 广播 `255.255.255.255` | 组播 `224.0.0.9`（同时兼容收听广播） |
| 认证 | 无 | 支持简单 / MD5 认证 |
| 自动汇总 | 强制按主类汇总 | 默认开启，可 `undo summary` 关闭 |
| 手动汇总 | 无 | `rip summary-address` 支持 |

**互通规则（本课重点）**：
- **RIPv2 向后兼容 RIPv1**：RIPv2 路由器能收听 RIPv1 的广播报文。
- **RIPv1 不兼容 RIPv2**：RIPv1 只收广播，收不到 RIPv2 的组播报文。
- 结论：混跑网段必须统一版本。要么全网 v2，要么把高版本一侧的接口降为 v1（华为支持**接口级 `rip version` 覆盖全局版本**）。
- 现代配置一律使用 **RIPv2 + `undo summary`**。

## 5. 华为 RIP 配置与验证（15 分钟）

### 5.1 基本配置（以 RIPv2 为例）

```system-view
[R1] rip 1
[R1-rip-1] version 2
[R1-rip-1] undo summary
[R1-rip-1] network 10.0.0.0
```

- `rip 1`：进入 RIP 进程，进程号 1（本地有效，类似 OSPF 进程号）。
- `version 2`：全局版本，各接口默认继承。
- `undo summary`：关闭 RIPv2 默认的自动汇总，避免子网被压缩成主类路由。
- `network 10.0.0.0`：开启 10.0.0.0/8 内所有接口的 RIP。注意：RIP 的 `network` 是“接口开关”，宣告的是接口所在的主类网段，不是 OSPF 那样带反掩码的精确宣告。

### 5.2 接口级版本覆盖、认证与汇总

```system-view
[R1-GigabitEthernet0/0/0] rip version 1                          // 该接口降级为 RIPv1
[R1-GigabitEthernet0/0/0] rip authentication-mode simple Huawei  // 简单认证（仅 v2 有效）
[R1-Serial2/0/0] rip authentication-mode md5 usual Huawei        // MD5 认证
[R1-Serial2/0/0] rip summary-address 10.1.0.0 255.255.254.0      // 手动汇总为 /23
```

### 5.3 静默接口

```system-view
[R1-rip-1] silent-interface GigabitEthernet0/0/1
```

只收不发，用于连接终端等不需要对外通告的接口（如接 PC 的下行口）。

### 5.4 查看命令（三板斧）

```system-view
[R1] display rip 1 route                    // 看 RIP 学到的路由与跳数
[R1] display rip neighbor                   // 看 RIP 邻居及对方版本
[R1] display ip routing-table protocol rip  // 看全局路由表中 RIP 来源的路由
[R1] display rip 1                          // 看进程配置与定时器
```

**优先级提醒**：RIP 路由默认 Pre=100（华为默认：直连 0 / OSPF 10 / 静态 60 / RIP 100 / BGP 255）。与“静态路由优先级 60”呼应——当多个协议学到同一网段时，**先比优先级，再比度量**。

## 6. eNSP 实验：官方示例 1-1 RIPv1&v2（25 分钟讲解 + 课下实操）

### 6.1 打开拓扑

- eNSP → 文件 → 打开 → `D:\Tools\Huawei\eNSP\examples\1-1RIPv1&v2\1-1RIPv1&v2.topo`
- 启动全部设备。官方示例已预置配置（vrpcfg），四台均为 AR1220。

### 6.2 拓扑解读

```
    [R2] GE0/0/0:10.0.123.2/24 ─┐              [R1] GE0/0/0:10.0.123.1/24 ─┐
  Lo0:10.0.2.2/24               ├── CLOUD1 ────┤                           │
    [R3] GE0/0/0:10.0.123.3/24 ─┘   (内部交换机,  └  [R1] S2/0/0:10.0.14.1/24
  Lo0:10.0.3.3/24                  广播网段             │ PPP Serial
                                                      [R4] S2/0/0:10.0.14.4/24
                                                   Lo0:10.1.0.1/24
                                                   Lo1:10.1.1.1/24
```

- **R1 / R2 / R3** 通过 CLOUD1（未绑定真机网卡的云，eNSP 内部当交换机用）构成共享以太网段 **10.0.123.0/24**。
- **R1 ↔ R4** 之间是 Serial PPP 链路，网段 **10.0.14.0/24**。
- R4 用两个 Loopback 模拟需要通告的“业务网段”：10.1.0.0/24 与 10.1.1.0/24。

### 6.3 官方预置配置对照

**R1**（全局 v2，GE 口降为 v1，串口 MD5 认证）
```system-view
sysname R1
interface GigabitEthernet0/0/0
 ip address 10.0.123.1 255.255.255.0
 rip authentication-mode simple Huawei
 rip version 1
interface Serial2/0/0
 link-protocol ppp
 ip address 10.0.14.1 255.255.255.0
 rip authentication-mode md5 usual Huawei
interface LoopBack0
 ip address 10.0.1.1 255.255.255.0
#
rip 1
 undo summary
 version 2
 network 10.0.0.0
```

**R2**（RIPv1）
```system-view
sysname R2
interface GigabitEthernet0/0/0
 ip address 10.0.123.2 255.255.255.0
 rip authentication-mode simple Huawei
interface LoopBack0
 ip address 10.0.2.2 255.255.255.0
#
rip 1
 undo summary
 version 1
 network 10.0.0.0
```

**R3**（RIPv1，同 R2 结构）
```system-view
sysname R3
interface GigabitEthernet0/0/0
 ip address 10.0.123.3 255.255.255.0
 rip authentication-mode simple Huawei
interface LoopBack0
 ip address 10.0.3.3 255.255.255.0
#
rip 1
 undo summary
 version 1
 network 10.0.0.0
```

**R4**（全局 v2，串口 silent + 汇总）
```system-view
sysname R4
interface Serial2/0/0
 link-protocol ppp
 ip address 10.0.14.4 255.255.255.0
 rip summary-address 10.1.0.0 255.255.254.0
interface LoopBack0
 ip address 10.1.0.1 255.255.255.0
interface LoopBack1
 ip address 10.1.1.1 255.255.255.0
#
rip 1
 undo summary
 version 2
 network 10.0.0.0
 silent-interface Serial2/0/0
```

### 6.4 阶段一：验证官方配置下的行为

1. **R1 看路由**：`display ip routing-table protocol rip`
   - 应看到 10.0.2.0/24、10.0.3.0/24（均 1 跳，从 R2/R3 经 GE 学到）。
   - **注意：没有 10.1.0.0/23！** 因为 R4 的串口配置了 `silent-interface`，只收不发，R1 收不到 R4 的通告。
2. **R4 看路由**：`display rip 1 route`
   - 应看到 10.0.1.0/24、10.0.123.0/24（1 跳）、**10.0.2.0/24 与 10.0.3.0/24（2 跳，经 R1 中转）**——直观看到“跳数逐跳累加”。
3. **看邻居与版本**：`display rip neighbor`
   - R1 侧看到邻居 10.0.123.2 / 10.0.123.3，版本为 v1。
   - R4 侧看到邻居 10.0.14.1（R1），版本为 v2。
4. **Ping 测试**：
   - R1 ↔ R2（10.0.2.2）、R1 ↔ R3（10.0.3.3）：通。
   - R4 ↔ R1（10.0.1.1）：通。
   - **R1 → R4 的 Loopback（10.1.0.1 / 10.1.1.1）：不通**——因为 R4 串口 silent，R1 根本没有去 10.1.0.0 的路由。这就是“静默接口只收不发”的直接后果。

### 6.5 阶段二：RIPv1 与 RIPv2 互操作实验（本拓扑的核心）

在 R1 的 GE0/0/0 上取消接口级 v1 降级：

```system-view
[R1-GigabitEthernet0/0/0] undo rip version
```

此时 R1 的 GE 口继承全局 v2，改发 RIPv2 组播 `224.0.0.9`。观察 R2：

```system-view
[R2] display ip routing-table protocol rip
```

- 等 180 秒老化后，**10.0.1.0/24 从 R2/R3 消失**（RIPv1 收不到 RIPv2 组播）。
- 而 R1 仍能学到 R2/R3 的路由（RIPv2 兼容 RIPv1 广播）——**出现“单向学习”**。

**结论**：混跑网段必须统一版本。把 R1 的 GE 口恢复 `rip version 1`，全网 GE 网段统一为 v1，互通恢复。这正是官方配置里那句接口级 `rip version 1` 存在的意义。

### 6.6 阶段三：认证、汇总、静默的细节

- **汇总**：R4 串口 `rip summary-address 10.1.0.0 255.255.254.0`，把两个 /24 业务网段汇总为 10.1.0.0/23 再通告。注意它要生效的前提是 R4 串口**能发**（silent 会把它挡住）。
- **认证方向性**：R1 串口要求 MD5 认证，而 R4 未配置——即使去掉 silent，R1 也会丢弃 R4 发来的未认证报文。**认证必须在链路两端匹配**（与 OSPF 同理）。
- **细节提示**：GE 网段实际运行 v1，而 **RIPv1 报文没有认证字段**，所以 R1/R2/R3 GE 口上的 `rip authentication-mode simple` 在该网段实际不生效（认证仅对 RIPv2 有效）。

### 6.7 阶段四（挑战）：修复为全互通

在 R4 上补齐认证并去掉 silent：

```system-view
[R4] interface Serial2/0/0
[R4-Serial2/0/0] rip authentication-mode md5 usual Huawei
[R4] rip 1
[R4-rip-1] undo silent-interface Serial2/0/0
```

- 观察 R1：`display ip routing-table protocol rip` 出现 **10.1.0.0/23（1 跳）**，Ping R4 的两个 Loopback 均通。
- 若在 R4 串口执行 `undo rip summary-address`，R1 会看到两条 /24 明细路由——对比体会“汇总 vs 明细”对路由表规模的影响。
- 注意：R4 从 R1 学到的路由（10.0.1.0/24 等）**不会**再通告回 R1——这正是**水平分割**在后台工作，防止环路的体现。

## 7. 现网深度关联：为什么现网不用 RIP？（10 分钟）

- **现状**：运营商现网 IGP 是 OSPF / ISIS；RIP 基本绝迹，仅少量老旧设备、小规模工业/嵌入式网络可能残留。
- **被淘汰的原因**：慢收敛、存在环路风险、只看跳数不看带宽、有类设计的历史包袱。
- **学 RIP 的价值**：它是动态路由的“最小完整实现”——协议选路、度量、通告、收敛、防环这些概念在 OSPF 中全部复用。把 RIP 摸透，第 7 课学 OSPF 时只需关注“链路状态 vs 距离矢量”带来的革命性差异。
- **排障提示**：若真遇到老网络跑 RIP，先看 `display rip route` 跳数是否接近 16、版本是否混跑、认证两端是否匹配、silent 接口是否误配。

## 8. 课堂小结与课后任务（5 分钟）

**核心回顾**：
- 距离矢量 = “道听途说”，只报方向和距离；度量用跳数，**15 通、16 断**。
- 环路来自收敛期的“记数到无穷”，防环靠水平分割 / 毒性逆转 / 触发更新 / 抑制计时器。
- **RIPv2 兼容 v1、v1 不兼容 v2**；混跑时用接口级 `rip version` 降版统一。
- RIP 路由优先级 100；现网用 OSPF/ISIS，RIP 是教学跳板。

**课后任务（eNSP，继续使用 1-1RIPv1&v2 拓扑）**：
1. 用 `display current-configuration configuration rip` 把四台设备配置读一遍，说出每台设备的“角色”（版本、认证、汇总、silent）。
2. 完成阶段二实验，在 GE 网段抓包对比 RIPv1 广播（255.255.255.255）与 RIPv2 组播（224.0.0.9）的报文差异。
3. 完成阶段四修复，验证 R1 学到 10.1.0.0/23，并对比删除汇总命令前后的路由表。
4. 思考题：R4 从 R1 学到了 10.0.2.0/24（度量 2），为什么修复后 R1 反而收不到这条路由？请用水平分割解释。
5. 预习第 7 课：同样是“路由自动学习”，OSPF 为什么能做到无环、快收敛？与 RIP 的根本差别在哪里？
