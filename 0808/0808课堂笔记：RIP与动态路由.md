# 8.8 课堂笔记：RIP（动态路由第一课）

说明：录音只保留下来一句话，这份笔记以它为课堂重点；其余内容按讲义整理，只作复习参考，不代表课堂上强调过。

## 一、课堂重点（录音原话）

> "名义上是一跳一跳过去的，但实际上逻辑上来讲，它其实是一个专用链路。"

这句话拆成两层来记：

**"名义上一跳一跳"——说的是逐跳转发。** 报文经过的每台路由器，都只做当前这一跳的决定：查路由表（去哪个网段、交给谁、从哪个接口出）→ TTL 减 1 → 重新封装二层头 → 发给下一跳。整个过程源/目的 IP 不变，每跳变的只是 MAC 封装。

**"逻辑上其实是一个专用链路"——最可能说的是 PPP 链路。** 录音上下文不全，但结合本课拓扑（实验里 R1↔R4 就是 Serial PPP），PPP 是点到点协议，链路上只有唯一对端，逻辑上等同一根专线把两台路由器直连：不用 ARP 查下一跳的 MAC，NextHop 没有歧义。

对比着记三种链路：

- **以太网**：一个接口所在网段可能挂着好几台路由器，必须靠 NextHop + ARP 确定这一跳具体交给谁。
- **PPP 点到点**：对端唯一，逻辑上就是专用链路，没有"交给谁"的问题。
- **直连路由**：中间没有下一台路由器，目标主机自己就是下一跳。

## 二、以下内容来自讲义（录音未覆盖，仅作复习参考）

### RIP 工作原理

距离矢量协议，"道听途说"：每台路由器每 30 秒把整张路由表发给邻居，邻居发现"你告诉我的路比我现在的更近（跳数少）"就更新，下一跳指向你，再往外传时跳数 +1。

度量只有跳数：每过一台路由器 1 跳，直连 0 跳；**15 跳可达，16 跳不可达**。只认跳数不认带宽——2 跳的百兆路径会赢过 3 跳的千兆（讲义原文这句写反了）。RIP 路由优先级 Pre=100（直连 0、OSPF 10、静态 60）。

定时器：更新 30s、老化 180s、垃圾收集 120s（老化后再等 120s，共 300s 彻底删除）。

### 环路：记数到无穷

网段断了之后，两台路由器的旧路由互相把 NextHop 指向对方，包在两者之间来回弹，跳数一路加到 16 才判不可达——"记数到无穷"，这是 RIP 慢收敛、易环路的根源。

防环四招：水平分割（从哪学的不从哪通告回去）、毒性逆转（主动向来源回告 Metric=16）、触发更新（一变立刻通告，不等 30 秒）、抑制计时器（标不可达后一段时间内不接受更差的路由）。

### RIPv1 与 RIPv2

| | RIPv1 | RIPv2 |
|---|---|---|
| VLSM/CIDR | 不支持（按主类） | 支持 |
| 通告方式 | 广播 255.255.255.255 | 组播 224.0.0.9 |
| 认证 | 无 | 简单 / MD5 |
| 自动汇总 | 强制按主类 | 默认开启，可 `undo summary` 关闭 |

互通规则：v2 能收 v1 的广播（向后兼容），v1 收不到 v2 的组播，混跑会出现"单向学习"。解决办法是统一版本，华为支持接口级 `rip version` 覆盖全局版本。注意别把"v2 一定收得到 v1"当绝对结论，排障时看接口实际收发模式。

### 配置与实验

基础配置：

```
rip 1
 version 2
 undo summary
 network 10.0.0.0
```

`network 10.0.0.0` 是"接口开关"：落在 10.0.0.0/8 里的接口都参与 RIP，不是宣告一条 10.0.0.0/8 路由，也不像 OSPF 那样带反掩码精确宣告。

实验用 eNSP 官方拓扑 1-1RIPv1&v2（四台 AR1220）。R1 学不到 R4 的 Loopback 路由，原因是一串，要逐项过：

1. **版本**：R1 进程是 v2，但连 R2/R3 的 GE 口被接口级降成了 v1。
2. **认证**：R1 串口配了 MD5，R4 没配，R1 会丢弃 R4 的未认证报文。认证要两端匹配；且 RIPv1 报文没有认证字段，GE 网段跑 v1，那几句 simple 认证实际不生效。
3. **silent-interface**：R4 串口只收不发，R1 根本收不到 R4 的通告。（R4 没配认证，收 R1 的报文不受影响，所以 R4 能学到 R1 侧路由。）
4. **汇总**：R4 串口配了 `rip summary-address 10.1.0.0 255.255.254.0`，两个 /24 汇总成 /23 通告——前提是串口能发，silent 会挡住它。

排查顺序：接口和直连路由 → RIP 是否在接口使能 → 版本 → 认证 → silent → 汇总 → RIP 路由与全局路由表 → 最后才 Ping、抓包。

常用命令：

```
display rip 1 route                    // RIP 学到的路由和跳数
display rip 1 neighbor                 // 邻居及对方版本
display rip 1 interface                // 接口级状态（版本、认证、silent）
display ip routing-table protocol rip  // 全局表里的 RIP 路由
display current-configuration configuration rip
```

修复（挑战阶段）：R4 串口补 `rip authentication-mode md5 usual Huawei`，再 `undo silent-interface`。之后 R1 应看到 10.1.0.0/23（1 跳），Ping 通 R4 两个 Loopback；undo 汇总命令则看到两条 /24 明细。

### 几处容易记错的

- 讲义"2 跳百兆会输给 3 跳千兆"写反了，RIP 只数跳数，2 跳的赢。
- 认证不匹配时，受影响的是"要求认证却收到未认证报文"的那一侧；没配认证的一侧照收不误。
- OSPF 收敛完成后无环，但收敛过程中可能有短暂 micro-loop，别记成"任何时候绝对无环"。

旧 AR1220/eNSP 镜像的具体行为，以 display 输出和 UDP/520 抓包为准。
