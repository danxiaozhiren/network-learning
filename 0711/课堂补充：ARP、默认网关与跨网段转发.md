# 课堂补充：ARP、默认网关与跨网段转发

## 讲义说明

- **内容来源**：根据 7 月 11 日课堂后半段实际讲解补充整理
- **前置知识**：IP 地址、子网掩码、MAC 地址、交换机 MAC 地址表、VLAN 基本原理
- **学习目标**：能够完整解释一个 Ping 包在同网段和跨网段场景下如何查找 MAC、如何到达网关、如何被路由器逐跳转发

## 1. PC 发送报文前，先做什么？

PC 要与一个目标 IP 通信时，第一步不是直接发 Ping，而是先根据本机路由表判断报文应该从哪个接口发出、交给哪个下一跳。

在最基础的单网卡场景中，可以先用 IP 地址和子网掩码判断目标是否在本地网段：

```text
本机网络地址 = 本机 IP AND 子网掩码
目标网络地址 = 目标 IP AND 子网掩码
```

- 两个网络地址相同：目标在本地网段，尝试直接交付。
- 两个网络地址不同：目标在其他网段，查找更具体的路由；如果没有，通常使用默认路由将报文交给默认网关。

```text
                    目标 IP
                       │
                       ▼
              查看本机路由表
                       │
              ┌───────┴───────┐
              ▼               ▼
         目标在本地网段     目标在其他网段
              │               │
      ARP 查目标主机 MAC   ARP 查下一跳 MAC
              │               │
          直接交付         交给默认网关
```

---

## 2. ARP 解决什么问题？

ARP（Address Resolution Protocol）用于在本地二层网络中，根据已知 IPv4 地址查找对应的 MAC 地址。

### 2.1 ARP 请求

ARP Request 采用二层广播发送：

```text
目标 MAC：FF:FF:FF:FF:FF:FF
问题：谁拥有 10.1.1.2？请告诉 10.1.1.1。
```

同一广播域内的设备都能收到请求，但只有拥有该 IP 的设备应该回复。普通路由器不会把这个二层广播转发到其他广播域。

### 2.2 ARP 回复

目标主机收到请求后，通常使用单播 ARP Reply 回复自己的 MAC 地址。发起方把 IP 与 MAC 的对应关系暂存在 ARP 表中，后续通信可直接使用，不必每发一个报文都重新查询。

### 2.3 为什么第一次 Ping 可能较慢或丢一个包？

如果 ARP 表中还没有目标或下一跳的 MAC，设备需要先完成 ARP 解析，才能封装并发送 ICMP 报文。因此，第一个 Ping 包延迟较高或丢失，不一定代表网络持续中断。

## 3. 同网段通信过程

示例：

```text
PC1：10.1.1.1/24
PC2：10.1.1.2/24
```

PC 1 Ping PC 2 时：

1. PC 1 查看路由表，判断 `10.1.1.2` 位于本地 `10.1.1.0/24` 网段。
2. PC 1 查看本机 ARP 表。
3. 如果没有 `10.1.1.2` 的记录，PC 1 广播 ARP Request。
4. PC 2 回复自己的 MAC。
5. PC 1 把 ICMP Echo Request 封装成目标 MAC 为 PC 2 MAC 的以太网帧。
6. 交换机根据目标 MAC 和所属 VLAN 将帧转发给 PC 2。

| 字段 | 内容 |
|------|------|
| 源 IP | `10.1.1.1` |
| 目标 IP | `10.1.1.2` |
| 源 MAC | PC 1 的 MAC |
| 目标 MAC | PC 2 的 MAC |

如果 `10.1.1.2` 不存在，PC 1 会重试 ARP Request；始终没有设备回复时，便无法封装目标 MAC，本次通信失败。

---

## 4. 默认网关的作用

默认网关是主机发往其他网段时通常使用的下一跳。可以把它理解为：

> 目标不在我的本地网段，我不知道后续的完整路径，先把报文交给网关处理。

默认网关必须是主机当前出口二层可达的下一跳。在普通以太网中，网关 IP 通常与主机的 IP 位于同一子网，这样主机才能通过 ARP 获得网关 MAC。

**注意**：默认网关不是主机自动“发现”的神秘设备，它需要通过手动配置或 DHCP 下发给主机。

## 5. 跨网段转发的完整过程

### 5.1 实验拓扑

```text
PC1                  R1                         PC2
10.1.1.1/24          G0/0/0 10.1.1.254/24       100.1.1.5/24
GW 10.1.1.254   ---- G0/0/1 100.1.1.254/24 ---- GW 100.1.1.254
```

### 5.2 PC 1 发送报文

1. PC 1 判断 `100.1.1.5` 不在本地 `10.1.1.0/24` 网段。
2. PC 1 查路由表，命中默认路由，下一跳为 `10.1.1.254`。
3. PC 1 通过 ARP 查询 `10.1.1.254` 的 MAC，**不会查询 `100.1.1.5` 的 MAC**。
4. PC 1 封装并发送报文：

| 字段 | 内容 |
|------|------|
| 源 IP | `10.1.1.1` |
| 目标 IP | `100.1.1.5` |
| 源 MAC | PC 1 的 MAC |
| 目标 MAC | R1 G0/0/0 的 MAC |

### 5.3 路由器转发报文

1. R1 收到目标 MAC 为自己接口 MAC 的以太网帧。
2. R1 拆除当前二层头，读取内部 IP 包的目标 IP `100.1.1.5`。
3. R1 递减 TTL，再查询路由表，确定从 G0/0/1 发出。
4. 如果 R1 的 ARP 表中没有 `100.1.1.5`，R1 会在 G0/0/1 所在网段发送 ARP Request。
5. R1 学习到 PC 2 的 MAC 后，为 IP 包封装新的二层头。

| 字段 | 内容 |
|------|------|
| 源 IP | `10.1.1.1` |
| 目标 IP | `100.1.1.5` |
| 源 MAC | R1 G0/0/1 的 MAC |
| 目标 MAC | PC 2 的 MAC |

### 5.4 PC 2 回复

PC 2 判断 `10.1.1.1` 不在本地网段，因此把回程报文交给默认网关 `100.1.1.254`。R1 再根据路由表将报文转发回 PC 1。

### 5.5 跨网段转发的核心规律

在不考虑 NAT 的情况下：

- **源 IP 和目标 IP**：端到端基本保持不变。
- **源 MAC 和目标 MAC**：每经过一段二层链路都重新封装。
- **TTL**：每经过一台路由器通常减 1，防止 IP 包在三层网络中无限循环。

```text
第一段：PC1 MAC      -> R1 G0/0/0 MAC | 10.1.1.1 -> 100.1.1.5
第二段：R1 G0/0/1 MAC -> PC2 MAC       | 10.1.1.1 -> 100.1.1.5
```

路由器不是“完全不看 MAC”。它先接收当前链路上发给自己的二层帧，再拆掉当前二层头、按目标 IP 路由，最后为下一段链路重新封装二层头。

## 6. ARP、网关与 VLAN 的关系

| VLAN 关系 | IP 网段关系 | 结果 |
|-----------|-------------|------|
| 同 VLAN | 同网段 | 通过 ARP 和二层交换直接通信 |
| 同 VLAN | 不同网段 | 仍需要三层设备转发 |
| 不同 VLAN | 同网段 | 通常不通：主机直接广播 ARP，但 ARP 无法跨越 VLAN |
| 不同 VLAN | 不同网段 | 需要通过路由器子接口、VLANIF 或其他三层网关实现 VLAN 间路由 |

### 6.1 一个 VLAN 通常对应一个 IP 子网

例如：

```text
VLAN 10 -> 10.1.10.0/24 -> Gateway 10.1.10.254
VLAN 20 -> 10.1.20.0/24 -> Gateway 10.1.20.254
```

把同一个 IP 子网拆到不同 VLAN 中会导致主机的本地交付判断与实际二层可达性冲突，因此正常规划中应避免这样做。

### 6.2 不同 VLAN 如何互通？

不同 VLAN 之间的二层广播域相互隔离，需要三层网关完成路由：

- **路由器子接口**：交换机以 Trunk 连接路由器，路由器在一个物理接口下创建多个子接口，每个子接口终结一个 VLAN 的 802.1Q 标签并作为该 VLAN 的网关。这种方式称为单臂路由（Router-on-a-Stick）。
- **三层交换机 VLANIF**：直接在三层交换机上为各 VLAN 创建 VLANIF 网关，在设备内部完成 VLAN 间路由。

## 7. 实验与抓包观察

### 7.1 实验目标

1. 对比同网段 Ping 和跨网段 Ping 时 ARP 查询的对象。
2. 观察 IP 地址在路由前后是否变化。
3. 观察 MAC 地址在路由器两侧如何变化。
4. 理解第一个 Ping 包可能延迟较高或丢失的原因。

### 7.2 建议操作

1. 按第 5.1 节搭建 PC 1—R1—PC 2 拓扑。
2. 配置两个 PC 的 IP、掩码和默认网关。
3. 在 R1 的两个接口上配置 IP 地址并启用接口。
4. 先在 R1 两侧同时抓包，再从 PC 1 Ping PC 2。
5. 查看 PC 和 R1 的 ARP 表，查看 R1 的路由表。

华为 VRP 常用查看命令：

```text
display arp
display ip routing-table
display interface GigabitEthernet 0/0/0
display interface GigabitEthernet 0/0/1
```

### 7.3 抓包时的观察点

- Ping 前是否先出现 ARP Request/Reply。
- PC 1 发出的 ARP 查询的是否是默认网关 `10.1.1.254`。
- R1 另一侧发出的 ARP 查询的是否是 PC 2 `100.1.1.5`。
- 两侧 ICMP 报文的源 IP、目标 IP 是否一致。
- 两侧以太网帧的源 MAC、目标 MAC 是否不同。
- R1 转发后的 TTL 是否减 1。

## 8. 常见误区

### 误区一：跨网段时，PC 会 ARP 询问远端主机

**错误。** PC 通常只在本地链路上 ARP 查询下一跳。对于远端网段，这个下一跳通常是默认网关。

### 误区二：报文交给网关后，目标 IP 会变成网关 IP

**错误。** 目标 IP 仍然是最终目标主机；当前链路上的目标 MAC 才是网关 MAC。

### 误区三：路由器不看 MAC 地址

**不准确。** 路由器需要先在当前链路上接收二层帧，但它选择转发路径的核心依据是目标 IP 和路由表，而不是原帧的目标 MAC。

### 误区四：只要 IP 地址属于同一网段，就一定能通

**错误。** 同网段直接通信还要求二层可达。如果两台主机被划入不同 VLAN，ARP 广播无法到达对方，即使 IP 表面上属于同一网段，也不能按普通本地交付方式互通。

### 误区五：默认网关可以随便填一个其他网段的 IP

**错误。** 主机必须能在当前出口上到达下一跳。在普通以太网场景中，如果网关不在本地可达子网内，主机通常无法通过 ARP 获取它的 MAC。

## 9. 排错思路

跨网段 Ping 不通时，建议按以下顺序排查：

1. 检查两端的 IP 地址和子网掩码。
2. 检查默认网关是否配置正确。
3. 先 Ping 本机网关，验证本地二层网络和 ARP。
4. 检查 PC 和路由器的 ARP 表。
5. 检查交换机 Access 端口归属、VLAN 创建情况和 Trunk 允许列表。
6. 检查路由器的直连路由与其他路由。
7. 确认去程和回程都存在可用路由。
8. 最后再检查 ACL、防火墙等策略是否拦截报文。

---

## 10. 课堂小结

1. PC 先查路由表，再决定是直接交付还是交给下一跳。
2. 同网段通信时，ARP 查询的是目标主机 MAC。
3. 跨网段通信时，ARP 查询的是下一跳网关 MAC。
4. 跨网段时，IP 地址指向最终通信双方，MAC 地址服务于当前这一段二层交付。
5. 路由器拆掉当前二层头，根据目标 IP 和路由表选择下一跳，再重新封装二层头。
6. VLAN 隔离广播域；不同 VLAN 之间要互通，必须引入三层网关。

> **一句话记忆：同网段找目标 MAC，跨网段找网关 MAC；IP 看最终目标，MAC 看当前下一跳。**
